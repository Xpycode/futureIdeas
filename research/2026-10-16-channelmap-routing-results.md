# ChannelMap CM-E1 routing experiment — B6

**Date:** 2026-10-16 · **Result:** bounded synthetic routing gate passed. No app implementation or audible-playback acceptance.

## What passed

The final [run-02 results](experiments/channelmap/run-02/results.json) cover two generated inputs: one with a single eight-channel PCM stream; one with two distinct eight-channel PCM streams, selecting the **second** by absolute stream index. Both have unknown declared channel layout. Channels **5 then 2** (indices 4, 1) were exported as two mono WAVs and two ordered mono PCM tracks in MOV.

| Check | Result in both cases |
|---|---|
| PCM format | 48 kHz, signed 24-bit, mono per selected channel |
| Sample identity | All 48,000 samples per output channel matched independently generated integer references |
| WAV/MOV agreement | Both output forms matched the same expected channel bytes |
| Video copy | All 50 ordered ProRes packet sizes and SHA-256 payload hashes matched |
| Video timing | Packet presentation timestamps/durations matched; full two-second picture retained |
| Audio timing | Both selected tracks started exactly 1/4 second after video; one-second duration retained |
| Interior audio timing | Adjacent packet boundaries contiguous; PCM packet byte counts agree with sample durations |
| MOV edit lists | Independent narrow atom reader found 1/4-second empty edit followed by one second at media time zero, at rate 1 |
| Source integrity | Source digest unchanged after exports |

This establishes the tested FFmpeg path for these fixtures, including no video truncation when audio ends at 1.25 seconds. It does not establish universal codec, MOV edit-list or player behavior.

## Fixture and oracle design

The [reproducible harness](experiments/channelmap/routing_experiment.py) generates two sets of eight unique tones with integer markers and deterministic variation. Original integer channel byte arrays are the oracle; expected output is not generated by running the same routing filter a second time. The finished source MOV is decoded and checked against the original interleaved reference before any export is trusted.

The video fixture is 160×90, 25 fps, ProRes Proxy, two seconds. Audio is 48 kHz PCM24, one second, muxed with a 250 ms offset. The second input has deliberately different samples in its second audio stream.

Each saved plan records source size/digest, absolute stream index, ordered zero-based channel indices, expected count, rate, format and mono intent. Those selectors drive actual MOV/WAV commands. The harness rejects snapshot/topology mismatches before routing. Unknown layouts stay null; no surround meaning is inferred.

Export uses numeric pan mappings, explicit output maps, copied video, PCM24 audio, preserved timestamps and a 48 kHz MOV movie timescale. There is no gain, resampling, inferred pairing or shortest-stream policy. Plain WAV retains samples; its source A/V offset is recorded in the plan, not represented as a video relationship inside WAV.

Video comparison uses ordered packet payload hashes independently of presentation timestamps. Audio comparison uses raw PCM bytes and rational packet timing. A separate small ISO-BMFF reader inspects the generated files' edit lists; this reader is intentionally restricted to ordinary nonfragmented fixture atoms, not a production parser.

## Negative controls

All **13** controls were rejected:

- Actual alternate exports: reversed order, duplicated channel, off-by-one selection, wrong absolute audio stream, and reset audio timestamps.
- Actual mutated PCM WAVs: one changed sample; one removed sample.
- Actual MOV with one video packet dropped.
- Preflight: absent channel; mismatched expected topology.
- Actual generated-source copy modified after taking the expected snapshot.
- Oracle-only timestamp mutations: move one interior packet boundary forward or backward by one sample.

The timestamp-reset export retained identical PCM and failed offset/edit-list checks. The interior timestamp cases test the continuity assertion directly; they are not claims of malformed-MOV demux testing. Each preflight case requires its specific diagnostic rather than accepting any exception.

## Review and validation history

An independent agent reviewed the first harness. Run-01 passed its initial checks but only checked audio endpoints, so an interior timing defect could have escaped. Review also identified implicit edit-list interpretation, plan selectors duplicated outside the plan, and overly broad exception acceptance.

The coordinator added packet continuity and sample-duration checks, independent edit-list inspection, plan-driven selectors, exact preflight diagnostics, an actual changed-source copy and per-WAV counts/hashes. **Run-02 reran the full bounded experiment successfully after these changes.** Run-01 is retained as historical evidence and is superseded by run-02. The independent reviewer then inspected the revised code and recorded run-02 evidence and found no remaining blocking false-pass for bounded CM-E1; the reviewer did not independently rerun it.

Evidence includes complete argv arrays, process exit status, stderr, probe packets/streams, edit-list observations, plans, backend versions/build configuration, executable digests and harness digest. A process failure or missing helper cannot silently pass. Missing-helper classification is implemented but was not fault-injected in this run.

## Limits and next gate

Each output is validated before atomic no-clobber hard-link publication on the same filesystem. Successful earlier outputs can remain if a later export/check fails. This proves neither a multi-output transaction nor cancellation, disk-full, drive-removal, crash recovery or portable publication behavior.

Not tested: audible solo/mute/loop/gain, Apple/NLE playback, six-channel regression, AAC priming, 16/32-bit integer or float PCM, H.264/HEVC, cross-stream stereo pairing, fractional-frame/complex edit cases, timecode/rotation/color retention, personal recordings, user usefulness or signed-helper packaging.

The spec's PCM-only contradiction is reconciled: unchanged **PCM** streams may be copied where supported; retained compressed streams must decode to PCM in MVP. Compressed passthrough is deferred. This is proposal cleanup, not app selection or proof of that untested whole-stream path.

**B6 is complete for CM-E1 and its multi-stream/unknown-layout extension.** Track B7 for broader format, metadata and lifecycle evidence before any app implementation. B2–B5 and I1–I4 remain separate research work.
